# 备份舱（backup-bay）— 本地文件备份手册

`backup-bay@0.2` 保存**排除策略允许的项目普通文件和目录**，生成归档与同名 manifest。恢复先验证整包和逐文件清单，只写入显式指定的空目录。它不是业务全量快照，也不是来源认证、敏感内容审查或灾备验收。

本版修改自公开仓库 [YangXuebiao/ai-collab-methodology](https://github.com/YangXuebiao/ai-collab-methodology/tree/186bcd844d4f15cf5489a73d510b6ce2064d988f) 的 `backup-bay@0.1` 脚本和手册，按仓库 [CC BY 4.0](../LICENSE) 许可保留出处。修改依据为离线合成负例，未访问或验证私有上游、真实私有目录、既有备份或业务数据库。

## 使用前提

- Linux、Bash、Python 3.11+；使用 zstd 时还需本机 `zstd`。gzip 只用 Python 标准库。未验证其他操作系统。
- 只在维护者控制的本地目录操作；备份时暂停写入，恢复时独占目标目录。该工具不是防同一账号恶意进程或文件系统并发篡改的隔离边界。
- 配置文件保留 `backup-bay.conf` 文件名及简单 `key=value` 写法，可用引号。它按数据解析，不再 `source`；不支持 shell 展开、多行脚本、重复或未知字段。
- 归档、manifest、脚本和配置必须来自可信的受控位置。hash 证明二者内容对应，**不能证明来源可信**；公开或跨环境传递前仍需单独分类、审查和授权。

## 操作

在项目根执行：

```bash
# 生成：阶段、代码、出差；可选 ASCII tag 和说明
bash scripts/project-bay-backup.sh 阶段
bash scripts/project-bay-backup.sh 代码 checkpoint "合成回归完成"

# 校验库中全部归档及清单，按已验证的 created_utc 报告最新
bash scripts/project-bay-check.sh

# 演练会写入私有临时目录，完成后清理；不会改写当前项目
bash scripts/project-bay-restore.sh --dry-run backups/<舱名>.tar.zst

# 恢复到当前项目树之外的空目录；父目录须已存在
bash scripts/project-bay-restore.sh --target /tmp/recovered-project backups/<舱名>.tar.zst

# 离线回归；测试只创建临时合成项目，不读取真实备份
python3 -m unittest discover -s tests -v
```

归档在 `backups/`；命名含 UTC 时间、随机 ID 和可选 tag，避免同秒并发覆盖。归档及 manifest 以仅当前用户可读写的权限保存。不会自动删除旧备份；旧 `retain_code_bays` 不再生效，容量和保留策略由维护者另行管理。历史 `INDEX.md` 不更新，现状以校验后的 manifest 为准。

相对归档路径按脚本所在项目根解释；相对 `--target` 按调用者工作目录解释。`--dry-run` 与 `--target` 互斥；不带二者、旧的 `--yes`、在用项目目录、项目内子目录、非空目标、含符号链接的目标路径都会被拒绝。脚本不删除目标数据、不切换业务、不运行依赖重建提示、不导入 `dump.sql`。

**退出码：** 0 代表请求的校验、生成或隔离文件恢复成功；1 代表配置、完整性、数据缺失、限额或执行失败；2 代表命令参数错误。空备份库也返回非零。备份过旧只提示，不表示包损坏。同秒 `created_utc` 并列时按 `bay.id` 稳定排序，并明确不能据此推断实际先后；超过当前时间五分钟的时间戳拒绝。

## 排除和秘密边界

必选路径排除包括：`.publish`、`.ssh`、`.aws`、`.gnupg`、`.azure`、`.kube`、gcloud 配置目录、`private`、`secrets`、`credentials`，以及 `.env`、`.env.*`、常见私钥/凭证文件名；任意深度都适用。还排除 `.git`、`backups`、常见可再生产物，以及 `backup-bay.conf`（其运维命令可能含敏感参数）。`exclude_extra` 只能增加排除，不能覆盖必选策略。

这是保守的路径规则，会排除 `.env.example` 等可能无害的文件，也无法发现藏在普通源文件、说明、数据库输出或任意文件名中的业务机密。manifest 使用 `sensitivity_review: "not_performed"`，不再把配置布尔值当作“无秘密”证明。旧 `secrets_included=false` 可兼容读取但不产生安全结论；`true` 拒绝。`extra_include` 原本并未实现，非空现在明确拒绝。

不跟随符号链接；未被排除的链接和特殊文件导致生成失败。常规硬链接源会存成独立普通文件，不保留链接关系。内容中的秘密、文件分类、私有上游历史、传输安全和加密备份需要另行处理。`.gitignore` 不是外传边界。

## 清单和恢复语义

只接受本版 `backup-bay@0.2`。manifest 实际记录：

| 字段 | 含义 |
|---|---|
| `project` | 与可信本地配置一致的项目标识；不是签名身份认证 |
| `bay` | 文件名对应 ID、阶段、UTC 时间、tag、说明 |
| `content.entries` | 每个目录的路径/类型/普通权限；每个文件另含大小和 SHA-256 |
| `content.excluded_patterns` | 使用的路径排除规则 |
| `content.exclusion_policy` | `path-policy@1` |
| `content.sensitivity_review` | 固定 `not_performed` |
| `content.db_dump` | `not_configured` 或 `included` |
| `integrity` | 压缩后整包 SHA-256、字节数、gzip/zstd 类型 |
| `restore` | 与生成的恢复说明同源的文字提示 |

归档包含 `RESTORE.txt`，记录项目标识、生成 UTC 时间、格式和依赖提示；**不记录本机用户名、主机名或原绝对路径**。配置了导出且成功时额外包含 `dump.sql`。两个名字为生成内容保留；源项目根若已有同名文件，则拒绝备份，避免遮盖原文件。恢复后再次备份前，须人工将这些生成说明/导出作为证据另行保管，并配置经审查的 `backup-bay.conf`。

校验会检查 schema、项目对应、时间、后缀和压缩魔数、整包大小/hash、完整成员集合、每个文件的大小/hash，以及普通权限。绝对路径、`..`、反斜线、控制字符、重复成员、未列入清单的成员、缺失文件、符号/硬链接、设备/FIFO、特殊权限位和扩展属性都拒绝。还验证 tar 的块边界、文件零填充、终结零块，拒绝终结后的非零数据或串接的第二个 tar。支持的输入限额在配置中可见，包括压缩大小、解压字节数、单文件大小和成员数。

恢复前先在临时文件完整验证归档，再逐文件写入空目标并复核 hash。成功时目标包含清单中的文件与目录；不保留所有者、ACL、扩展属性、稀疏布局、修改时间或链接身份。磁盘满、权限变化等写入失败时返回非零，可能留下**部分写入的新目标**，不会删除它或自动重试覆盖；维护者应检查并选另一个空目录重试。

只把文件解出来不等于应用可运行。需要从可信来源保留脚本、配置模板和依赖，再核验配置、数据库导入、启动、业务状态、切换和回退。不要用直接 `tar -xf` 绕过验证去覆盖在用目录。

## 数据库、兼容性和未完成事项

`db_dump_hook` 为空时不访问数据库；非空时只执行维护者审核的命令和参数，不经 shell。管道/重定向等旧 shell 语法不支持。失败、空输出、超时或超出限额会中止，不发布“成功”包。导出命令在独立进程组运行；超时或结束时清理同组进程，父进程成功退出后仍有同组子进程也视为失败。主动脱离进程组的恶意进程不在此清理保证内；不能把它作为运行不可信代码的沙箱。导出命令本身仍是受信任可执行代码，可能访问真实数据库；本仓测试只使用 `printf`、`true`、`false` 等合成命令，不证明真实数据库事务一致性或可恢复性。

0.1 缺少完整逐文件契约，本版**不自动升级或恢复旧包**，也不删除它们。旧包须在经批准的隔离环境审查来源和敏感分类、建立独立核验清单后再制定迁移办法。曾生成备份是否含私有资料，应由维护者私下核查，不能从合成测试推断。

剩余范围：独立内容扫描/允许清单、真实业务恢复、数据库一致性、签名/可信来源、加密、异地与不可变副本、RPO/RTO、保留策略、主机故障和多平台测试。本版回归通过不等于这些验收通过。
