# 模板

七份可直接复制使用的模板。**建议放进你自己项目的 `docs/templates/`，让 AI 每次都从这里抄。**

| 模板 | 什么时候用 | 谁写 |
|---|---|---|
| [spec-template.md](spec-template.md) | 每个版本开始时 | 设计者 |
| [task-card.md](task-card.md) | 分派实现任务时（一份 spec 可拆多张） | 设计者 |
| [dev-status.md](dev-status.md) | 实现过程中（完成一批原子项就更新） | 实现者 |
| [qa-report.md](qa-report.md) | 每个版本验收时（**别省** —— 独立验收的载体） | 验收者 |
| [decision-request.md](decision-request.md) | 遇到 B 类决策时（见 [05-决策边界.md](../docs/05-决策边界.md)） | 任何人 |
| [handoff.md](handoff.md) | 上下文快满、或里程碑边界 | 任何人 |
| [completion-report.md](completion-report.md) | 一版做完后收尾（**别省** —— 给未来的你写的） | 设计者 |

---

## 怎么让模板真正生效

**模板的价值在于格式固定。**

如果每次用的格式都不一样，下一个读的人每次都要重新理解——**那文件契约就退化成了口头转述**。

**三个做法**：

1. **放进项目仓库**，不要放在你个人笔记里（AI 读不到你本机的笔记）
2. **在项目入口文件里指明模板位置**（比如 `CLAUDE.md` 里写"写 spec 用 `docs/templates/spec-template.md`"）
3. **每次都用** —— 第一次偷懒说"这次简单，就不写模板了吧"，之后就再也不会用了

## 按需精简

**模板不是越全越好。**

如果某个章节你的项目永远用不上，就**从你的模板里删掉**——但要在删的地方留一句"不适用，因为 X"，否则读的人分不清是"没考虑"还是"考虑过不用"。

**最小可用集**（时间紧的时候）：

- spec 里保留 **§一 背景与目标** + **§七 文件清单** + **§八 验收标准**
- 其余章节可以口头说，但**§八 不能省**——没有验收标准的 spec，写不写都一样

---

## 关于「不适用」

模板里很多章节标着"某情况下必填"。**不适用时不要直接删掉章节**，写上：

```markdown
## 六b、评估口径与基线
不适用 —— 本次改动不涉及指标/性能/算法，无可量化评估对象。
```

**为什么**：直接删掉的话，读者无法区分"作者考虑过并认为不适用"和"作者忘了写"。**这一行字花 3 秒，省掉一次追问。**
